# Task specification

## Task
Restore the Mac's current-tool generate → retrieve → revise journey by aligning the running Backend and resolving the measured artifact-locator blocker.

## Purpose
[p1-00](../p1-00-mcp-friction-run-mac/manifest.md) measured a completed original, but no retrieved image bytes or revision. Its [independent PASS](../p1-00-mcp-friction-run-mac/review.md) accepts that evidence-only record. The live Backend lacks the source's revision contract, and the client cannot fetch the relative Gallery URL unchanged. This bounded Phase 1 repair must be accepted before Producer releases p1-01/02; it does not replace their envelope/consolidation work or p1-05's exit proof.

## Outcome
An agent using today's MCP tools can retrieve actual original and revision image bytes from usable returned locators, with persisted revision lineage on a Backend launched from identified source. Producer has enough independent evidence to release the existing Phase 1 sequence.

## Scope
Included: inspect and align the existing Mac Backend process with identified repository source; preserve its configuration, database and Gallery locations; resolve the relative-URL/client boundary through the smallest supported locator or client-configuration correction; document that supported path; run one real original/revision journey over current-tool stdio. A controlled Backend restart is authorized after checking active jobs and preserving their state; record any required recovery. Inspect the existing baseline job before considering any repeat submission.

Only change product code when the two measured blockers require it. Prefer the existing runtime and retrieval mechanisms. A valid result may need runtime/configuration/docs changes only; explain why if no source defect is found. If locators change, retain existing tool names, arguments and response fields, use configured host URLs/paths, and preserve working absolute URLs. Returning a host path is sufficient only when the intended client actually reads that returned path. Do not require an agent to invent an origin, rewrite a locator after failure, or copy a file out of band to make the verification pass. Byte-fetch/read verification must be disclosed separately from MCP metadata calls.

Excluded: response-envelope redesign, tool consolidation, a wait tool, a general health/version-attestation subsystem, a permanent smoke-script framework, Windows workers, video, training, model downloads, architecture changes and aesthetic acceptance. Do not rewrite the original baseline or backfill its null lineage. Keep all models, datasets, outputs and Gallery records. A new unrelated failure is a reported blocker for Producer to scope, not permission for an open-ended repair.

Open questions: the exact loaded baseline Backend commit is unknown; process cwd and health do not establish it. A relative URL failing locally does not prove a missing file or broken HTTP endpoint. Coding diagnoses these boundaries before choosing a repair; neither finding needs another routine CTY confirmation under the [owner instruction](../../requests/2026-11-24-proceed-within-project-boundaries.md).

Read first: p1-00 raw transcript, friction accounting, manifest and review; [MCP](../../mcp.md), [setup](../../setup.md), [operating policy](../../OPERATING-POLICY.md); [revision lineage](../../memory/ordinary-generation-revision-lineage.md), [runtime source verification](../../memory/runtime-source-contract-verification.md), [compute scope](../../memory/compute-target-and-resource-scope.md) and [explicit LoRAs](../../memory/explicit-lora-list-semantics.md).

Inputs: reviewed evidence commit `3081952e0ba12a339ab7e60b8081ede61a131b7f`, approved baseline/spec `e443f2e22a17f3ca61f69527bdd392e703b0e88b`, and QA report commit `c377a02c808589b225a6d5f386d7e47cc865b939`. The original baseline remains a legacy/null-context record.

## Done when
- [ ] The actual Backend used by the MCP client is launched from identified, clean source and exposes the revision-context contract. Check: manual. Evidence: full source SHA, launch command/cwd and process identity, relevant source fingerprints, effective non-secret data/URL configuration, and live OpenAPI fields. A checkout hash or healthy ping alone is insufficient; disclose the source and process transition, active-job check and any restart/recovery.
- [ ] The current Gallery tools provide a supported locator that the intended client consumes to retrieve actual original image bytes. Check: behavioral tests for any locator change and a real byte fetch/read using the returned locator. Evidence: raw tool result, consumed locator, retrieval command/result, byte size, SHA-256 and successful image decode. Demonstrate the baseline artifact remains accessible without changing its record; do not infer file/endpoint failure from the earlier local URL exception.
- [ ] One fresh current-tool stdio run generates and retrieves both an original and a revision, with the same request reference and a new brief revision, using the original's canonical artifact ID as `parent_artifact_id`. Check: manual. Evidence: ordered timestamped raw calls/results, both job/image/artifact identities, decoded image-byte hashes, and persisted original/revision context in status and Gallery records. The Backend-derived parent job/request/brief matches the original. Check an existing job after a timeout before resubmitting; disclose every intervention. A blocked journey does not satisfy this item.
- [ ] Software changes have meaningful behavioral regression coverage and passing checks for every changed component. Check: tests. Evidence: commands, exit codes, durations and results; use `--timeout=60` for long pytest suites and isolated roots below TMPDIR. Run the full suite for a changed Backend/MCP component; a reviewed unchanged-source suite may be reused with source equivalence recorded. Do not remove feature tests to conceal a defect. No unrelated Frontend or Windows result is implied.
- [ ] Producer and independent QA can inspect the exact delivered commit and distinguish repair verification from the no-repair baseline. Check: manual review. Evidence: `manifest.md`, complete redacted transcripts/configuration and byte-verification receipts, uploaded deliverables, a list of all source/config/runtime changes, and F4/F5/F8 resolution plus remaining F1/F2/F3/F6/F7 mappings. Preserve the original 23-unit/eight-incident accounting; state repair interventions separately. No three-run exit, aesthetics or owner-demo acceptance is claimed.
