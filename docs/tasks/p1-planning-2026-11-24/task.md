# Task specification

## Task
Assess published main, prepare the Phase 1 backlog and start the authorized kickoff/dispatch path.

## Purpose
Phase 0 is complete. The later owner instruction authorizes executable work
inside existing boundaries and delegates routine reference choices. This round
turns the existing Phase 1 scope into an ordered backlog and starts its review
and dispatch path without adding a routine confirmation gate.

## Outcome
CTY can inspect the adopted choices and work order; QA reviews the first kickoff;
Producer dispatches after CLEAR and tracks delivery through native prerequisites.

## Scope
Included: source and specification assessment at published main; a native plan;
recipient-owned coordination/review cards and dependency edges; application of
the later owner direction; CURRENT/PROGRESS and the project-channel report.
Excluded: Producer doing software implementation, aesthetic acceptance or changing
phase boundaries. Coding owns execution; QA owns independent review.
Open questions: none requiring CTY now; demonstrated boundary changes still escalate.
Read first: [owner request](../../requests/2026-11-24-fresh-producer-planning.md),
[roadmap](../../roadmap/ROADMAP.md), [CURRENT](../../CURRENT.md),
[MCP decisions](../../decisions/mcp.md), all `docs/tasks/p1-0*/task.md`, and
[team workflow](../../team/README.md).

- [ ] Source, existing specifications and current methods have been assessed against a fetched published commit. Check: manual. Evidence: the assessment and baseline in [plan.md](plan.md).
- [ ] The native backlog identifies owners, prerequisites, order and testable outcomes, including the CLEAR/build/exact-commit-review handoffs. Check: manual plus native readback. Evidence: plan links and saved blocker edges.
- [ ] The later owner direction and adopted ordinary choices are recorded with provenance; the actionable first kickoff/dispatch path is released. Ask through native cards only if a real boundary decision remains. Check: native and source readback. Evidence: owner-request file, revised specs and released recipient card.
- [ ] CURRENT, PROGRESS, the native plan and the channel report agree on first work, gates and next actors. Check: manual. Evidence: committed documents and the issue's recorded disposition.

## Delivery

- Known limitations: planning and read-only service checks establish no generation or phase-exit result. Long delegated execution continues on child cards with real blocker edges.
