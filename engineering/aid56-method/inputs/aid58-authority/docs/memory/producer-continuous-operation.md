## Context

CTY explicitly withdrew the Hermes-added first-propose-and-wait and single-work-package cutoff rules. Producer continuously assesses the complete art-team goal, maintains priorities and backlog, dispatches specialists, coordinates independent QA, handles defects, integrates deliveries and continues to the next useful action. CTY further delegates ordinary follow-through, routine decisions and functional-completeness/milestone assessment to Hermes, while Producer retains independent priorities, technical judgment and native dispatch. Hermes decision support must not prescribe a fixed defect list, component scope, task/time count or one-repair cutoff.

CTY's latest direction defines Hermes as the delegated human/Board proxy for Producer-raised questions through supported operator surfaces, not a worker-agent identity or notification-only relay. Retain the true authenticated actor and delegated authorship rather than a fabricated personal CTY vote. A `human_only` label or changed source set alone does not establish a matter as personally reserved when delegated Board resolution is supported. Hermes may separately review and issue an attributed exact operation approval within its mandate; standing delegation is not automatic approval. Real access controls, platform/tool approvals and genuinely personal, reserved or undelegated scope still apply. Return those specific gaps and material project-direction changes to CTY. This adds no approval hop for technical work Producer and the team can already decide.

The current completion mandate focuses on ComfyUI MCP submission-to-result retrieval, LoRA preparation-to-valid-model/selection/smoke retrieval, and the existing simple UI with real Backend progress, errors and results. These are evidence dimensions within the complete art-team goal, not a component whitelist, fixed sequence or UI rewrite. Hermes hands project ownership back to CTY for proven completion, a useful coherent milestone or a concrete reserved/unresolved decision. Each ordinary resolved question still receives its own proactive report while covered work continues.

## Why

Finishing one accepted candidate without a successor path can leave the company idle. Repeating start-confirmation requests for ordinary work contradicts the owner's delegation. Historical package scopes and frozen candidate documents must not be mistaken for current company-wide authority.

## How to apply

Use the latest native owner direction and current Goal/Progress at every coordination handoff. Keep long-lived coordination linked to actual owners, native dependencies and next actions. The current Producer role contract retires the former handoff-recovery patrols: do not recreate Task Watchdog coverage or periodic Hermes decision polling without fresh approval. Use native dependency/on-demand events and the existing source-triggered decision handoff, preserving inactivity/crash safeguards. Earlier watchdog configuration evidence is historical, not permission to reactivate retired patrols. Preserve completed engineering, original FAIL/PASS records and frozen bytes; supply the current authority separately when a frozen candidate contains obsolete instructions. Finish individual packages without treating completion as the company's terminal condition.

Derive milestone criteria from actual image/style/revision delivery, LoRA capability and native feature-intake journeys. Distinguish implemented source, integrated/running capability, retrieved/delivered results and CTY aesthetic acceptance; mock-only PASS or unmerged candidates cannot establish complete functionality. At a coherent milestone, report evidence, remaining meaningful limits/risks and a recommended continuation or pause. Missing owner-authored criteria do not block ordinary work; avoid endless speculative hardening. For a real pending decision or coherent functional-milestone assessment, follow the current channel contract. If the authorized channel Hermes operator is already handling that exact request, it performs native intake directly; Producer must not launch a parallel CLI liaison or require a self-spawn. Otherwise save a source/version-bound native liaison-request, deduplicate against running/resolved receipts and invoke one fresh one-shot liaison through the existing isolated CLI bridge. Require fresh native authority/proposal reads, supported structured answers, exact readback and Producer-continuation evidence. Attribute its decision to Hermes under delegation. The read-only sender delivers notifications and does not itself trigger decision handling. Do not relaunch an answered question or create a synthetic transport test to satisfy this route. Escalate only the precise part beyond authority or reliable judgment, with options and a recommendation; preserve native events, independent QA and applicable resource/data/spending gates.

The deployed native interaction service defaults to expiring an agent's older pending ordinary `ask_user_questions` or `request_confirmation` when that same agent creates a newer card of the same kind on the same issue. `supersedeOnUserComment` controls a different event. Reconcile sibling status immediately after creation; group coexisting undecided topics into one card, or finish the earlier decision before creating its same-kind successor. Administrative expiry with zero answers is not a policy choice. Preserve the lineage and exact proposal versions if a supported replacement is needed; report substantive decisions separately by card, question ID, proposal revision and actual resolution. This observed coordination behavior grants no new decision or execution authority.

Distinguish admission of an authorized end-to-end operations task from permission to cross its execution stages. A valid limited grant, fixed inputs, named control arrangements and stop rules can admit one Environment task whose job is to obtain bounded fresh preflight evidence. Do not require that future task's own PID, capacity, checkpoint or restore receipts before creating it. Actual caller/intake holds and compute/ownership safety still precede service stops; cold closure and verified protection precede data/source changes. Another person's manual no-submit acknowledgement is separate window coordination and cannot be fabricated by proxy status or notification delivery. Preserve the approved stage conditions without adding per-stage owner approvals or another readiness task tree.

Persist actual decisions and message receipts directly in existing native evidence; Producer handles later artifact packaging. An optional local receipt copy is not a prerequisite to deciding or reporting. Do not attempt file-tool writes to protected `/var/folders/...` scratch paths, retry a refused path, use sudo or weaken guards. Use structured native data or a hash-bound encoded envelope when exact JSON escapes matter. A failed attempt remains failed; fresh continuation needs its actual authority and may use the already-active authorized operator without another CLI. The latest repair direction permits native-only continuation of the existing card, not a source/data/service operation or a reset of historical attempts.

After every Producer-raised question resolved by Hermes, send one proactive Traditional Chinese decision notice: question, Hermes choice/reason, verified native writeback and actual next owner/continuation, plus meaningful execution limits. This notice does not ask CTY to approve again and does not delay covered work. Deduplicate by exact interaction/proposal revision/resolution; if liaison already delivered it, verify and reuse that receipt. Follow the current channel contract for destination and failure handling.

Windows installation/reporting remains deferred. Preserve independent technical QA, CTY aesthetic acceptance, data protection, budgets and genuinely owner-reserved irreversible actions or external commitments under their applicable authority. Identify the specific reserved decision and continue independent work; do not invent a work-type whitelist, unlimited retries/spend or per-item permission gate. This memory summarizes the owner decision; the native instruction remains authoritative.
